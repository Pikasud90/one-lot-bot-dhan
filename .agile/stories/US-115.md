# US-115: A way to run the whole test suite with the clock moved forward

## Story
As the owner, I want the whole test suite run as if it were a later date or hour, so that a test
that only passes while a date is still ahead is found before that date.

## Acceptance criteria
- AC1: Given scripts/gate_at.sh "2026-12-01T15:45+05:30", then it runs the full suite (`pytest -m
  "not live"`) with the wall clock frozen at that moment and moving on from it, and prints the tests
  that fail, with the clock it used.
- AC2: Given the option --fake-now, the plugin tests/clock_forward.py freezes `datetime.now`,
  `datetime.utcnow` and `time.time` for each test, so `onelot.clock.now_ist()` answers from that
  moment.
- AC3: Given a planted test that stamps 25 Nov 2026 15:45 and compares it with the real clock, when
  run at a later date, then the run fails it, and when run normally, passes it.
- AC4: Given the tests that read the real clock on purpose (timeouts, sleeps, threads), then each is
  marked `real_clock` and runs unfrozen, and the run lists them.
- AC5: Given the normal gate (scripts/gate.sh), then it is unchanged and does not read the plugin.
- AC6: Given the first run at three dates (the next trading day, a Saturday, and 15 Dec 2026 09:00),
  then the failures found are fixed or marked, or each one is listed in the log with its test.

## Non-functional requirements
- Frozen time must not break SQLite, threading or the wide list's background thread: tests that need
  real time are marked, not frozen.
- No change to src/: this is a test tool.
- The run takes about as long as the gate (26 minutes on 25 Nov): it is run on demand, not on every
  commit.

## Public contract
- `scripts/gate_at.sh` (new), `tests/clock_forward.py` (a pytest plugin, loaded only by `-p
  tests.clock_forward`), a marker `real_clock` in `pyproject.toml`.
- `freezegun>=1.5` is already in `requirements-dev.txt` (line 7) and in the venv, and no test uses
  it yet.
- `onelot.clock.now_ist()` (`src/onelot/clock.py` line 28), described as "the only sanctioned source
  of now".

## Notes & assumptions

Found in commit `6351599` (25 Nov 2026): `tests/delivery/test_delivery_round2.py` stamped a repeat
at "25 Nov 2026 15:45" and read it against the real clock, so it passed only while that day was
still ahead and failed from 15:45 on the day; the full gate caught it by luck. About 118 uses of
`now_ist()` and 41 test files read `datetime.now` or `now_ist()` (grep of `tests/`).

NOT in scope: rewriting the tests that read the clock (each failure found is its own small fix);
running the live desk; mocking time inside `src/`. Open question: none; the run dates in AC6 can
be changed by the owner.
