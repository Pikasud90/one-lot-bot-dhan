# US-030 — Paper trades visible on the desk (thin slice of US-016)

## Story
As the owner testing the paper book, I want to see every paper trade and its outcome on the desk, so that I can judge the alerts without reading the database.

## Acceptance criteria
- AC1: Given paper trades exist, when GET /api/paper is called, then it returns status counts (opened, filled, no_fill, closed, hook_errors) and the most recent 200 trades newest first with alert id, instrument, side, strategy, grade, status, close_reason, entry, exit (rupees as strings from integer paise), net and timestamps; read-only, same auth as other GET routes.
- AC2: Given the Desk page, then a Paper panel lists open paper trades and today's closed ones with status chips (pending, open, no fill, closed), entry/exit/net in rupees, grade (live or delayed) and close reason; it refreshes with the desk snapshot; Day theme default, large type, CSS variables only.
- AC3: Given no paper trades, then the panel says so; given paper.enabled false, then it says paper trading is off.

Manager clarifications (2026-11-01): contract: GET /api/paper -> {enabled, status: {opened, filled, no_fill, closed, hook_errors, desk_hook_errors}, trades: [...newest first, max 200], totals_today: {closed, wins, losses, gross_rupees, net_rupees (null until US-023)}}; each trade: alert_id, instrument (trading symbol / label), side, direction, kind, strategy, timeframe, grade, status, close_reason, qty, entry_ts, entry (rupee string from paise, e.g. '1000.30'), exit, gross, net (null when not yet computed), created_at, closed_at; rupee strings are derived from integer paise with Decimal, never float. Read the book through a PaperBook method (e.g. recent(limit) and today_totals(now)) that reads the DB, not the Desk lock. The Desk snapshot's paper block keeps the counts; the panel fetches /api/paper on each snapshot version change (not more than every 5 s). UI: Day theme default, large type, CSS variables only, both themes, mascots untouched; status chips pending/open/no fill/closed; net coloured with existing pos/neg classes; empty state and paper-off state. Same auth as other GET routes (US-005 hardens all reads later). US-002 (closing trades) is in progress in parallel; the panel must already show CLOSED rows correctly when they exist.
