# US-005 — Reads require authentication whenever the app is reachable off-loopback

## Story
As the owner, I want the app to ask for a passcode before showing anything when it is reachable from my LAN or phone, so that balances, holdings and alerts are not readable by anyone on the network.

## Acceptance criteria
- AC1: Given the server is bound off-loopback, when any of the GET API routes (except /, /static, the login endpoint and a minimal liveness probe) is called without a valid session, then it returns 401 and no data.
- AC2: Given the passcode login, when five wrong attempts occur within a minute from one client, then further attempts are refused for 60 seconds; the session cookie is HttpOnly and SameSite=Strict and expires after 12 hours of inactivity.
- AC3: Given the server is bound to loopback only, then behaviour is unchanged (no login) and the session token is no longer embedded in the page HTML for an unauthenticated off-loopback request.
- AC4: Given the passcode is stored, then only a salted hash is persisted (never the passcode), and rotating it invalidates all sessions.
