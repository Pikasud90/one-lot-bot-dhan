# US-018 — Frontend modules, accessibility and UI smoke tests

## Story
As the owner, I want a maintainable, accessible front end with automated checks, so that UI changes stop breaking features silently.

## Acceptance criteria
- AC1: Given app.js (about 1200 lines in one function), then it is split into ES modules per tab with no behaviour change, verified by a headless browser smoke test that loads every tab and asserts no console error.
- AC2: Given the day and night themes, then text contrast meets WCAG AA, every interactive control is keyboard reachable with a visible focus ring and has an accessible name.
- AC3: Given a network failure on any API call, then the tab shows a plain-language error with a retry, never a blank or frozen panel.
