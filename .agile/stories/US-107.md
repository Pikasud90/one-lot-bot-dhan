# US-107: An open page tells the owner when the server runs a new version

## Story
As the owner, I want an open browser tab to notice that the desk was restarted on new code, so that
I never watch a page that runs an old script against a new server.

## Acceptance criteria
- AC1: Given the page was served with build B and the stream now reports another build, when the
  next snapshot arrives, then a bar reads "The desk was updated. Reload this page." with a Reload
  button.
- AC2: Given a restart on the same code (same build), when the stream reconnects, then no bar
  appears.
- AC3: Given the bar is shown, when the owner presses Reload, then the page reloads and the bar is
  gone.
- AC4: Given GET /api/state and GET /api/health, then both carry status.build, a 12 character hex
  text, equal to the build in the page served by GET /.
- AC5: Given the page never loads a build (an old server), when snapshots arrive, then no bar
  appears and no error is raised.

## Non-functional requirements
- The bar never reloads the page by itself: the owner may be typing a note or reading a card.
- The build is computed once at start, from the bytes of the files under src/onelot/ui (not
  vendor/), so it costs nothing per request.
- No new dependency; no colour literal outside the theme blocks; text at least 14px.

## Public contract
- `onelot.api.server.create_app`: compute `build_id` once; `index()` replaces a new token
  `__BUILD__` in `src/onelot/ui/index.html`, next to `window.ONELOT_TOKEN` (line 734), by
  `window.ONELOT_BUILD`.
- `Engine.snapshot()` (`src/onelot/engine.py`, key `status`) gains `build` (None until the server
  sets it). `GET /api/health` returns `status` too, so both routes carry it.
- `src/onelot/ui/app.js`: `applyStream(payload)` (line 1007) compares `payload.state.status.build`
  with `window.ONELOT_BUILD`; one bar, in the warnings strip (`renderWarnings`).

## Notes & assumptions

Found by the lead on 25 Nov 2026 and in `.agile/sprints/sprint-04.md` ("reload the browser tab (an
open tab keeps the old page script)").

What exists today: `GET /` reads `index.html` on every request and `/static/...` is served with
`no-cache`, so a RELOAD always gets the new script. An already open tab keeps the script it loaded
and its `EventSource("/api/stream")` (app.js line 1019) reconnects every 3 seconds after a restart
and renders the new server's snapshots with the old code. Verified: `GET /api/health` returns only
`ok`, `health` and `status`; `status` has `started_at` but no version or build
(`src/onelot/__init__.py` has a fixed `__version__ = "2.0.0"`, which never changes). `started_at`
alone is not enough: a restart on the same code needs no reload.

NOT in scope: an automatic reload, a service worker, a version for the API contract. Open question
for the owner: none (the bar only informs).
