# US-090: the Volume Watch tab

Read `.agile/stories/VOL-API.md` first: it is the contract (words, formulas, JSON) between
this tab and the engine that another agent (US-089) builds at the same time. You build the
tab from the contract alone, with a fake engine in the page for development, exactly as the
Simulator tab was built (`src/onelot/ui/sim.js`, `sim.css`, `sim_fake.js`, the `?simfake=1`
switch and its "Demo data" banner: read them, they are the model for structure and style).

## What exists (read before designing)
- `src/onelot/ui/index.html`: the nav (`<a href="#sim" data-tab="sim">`), one
  `<section data-tab="..." class="tab">` per tab, feature files loaded after `app.js`.
- `src/onelot/ui/app.js` exports its helpers as `window.OneLot = { $, fmt, rup, cls, esc,
  pct, tsf, hhmm, store, toast, api, table, tabLoaders, tabShown, latest }`; a feature file
  registers `OneLot.tabLoaders.<name>`. Keys 1 to 8 switch tabs: find that code and make the
  new tab reachable the same way.
- Charts: the vendored TradingView Lightweight Charts (see how `sim.js` makes and sizes its
  chart, reads theme colours from CSS variables and redraws on a theme change).
- Themes: five, each one block of CSS variables in `styles.css`; `styles.css` may not gain a
  colour literal outside those blocks and your CSS uses variables only (see how `sim.css`
  and `mlstates.css` do it and which test checks it: `tests/acceptance/us030_helpers.py`).
- Owner's taste: bright Day theme by default, LARGE type (nothing under 14 px, body text at
  the size of the surrounding cards), plain words, no jargon without a legend.

## What to build
1. Nav entry "Volume" after "Live Desk" and a section with `<div id="volume-root">`; files
   `src/onelot/ui/volume.js`, `volume.css`, `volume_fake.js`. The header must still fit on
   one row at 1024 px wide (the UX pass of 23 Nov got 8 tabs on one row; with 9 check it and
   fix it by spacing or shorter labels, never by smaller type).
2. The page, top to bottom:
   a. Status line: "Live now" or "Stored session of 23 Nov" (`source`, `session`), the time
      of the last closed minute, and when the market is closed a plain banner: "The market
      is closed. This is the last session. The watch starts again at 09:15."; a date picker
      (today or a past date, `?date=`) and an index picker for the price line (`?index=`).
   b. Headline: the state as a chip (quiet, normal, busy, spike) and `now.text`; tiles:
      relative volume now, last 5 minutes, day so far; buyers' share last 5 minutes and day
      so far (a two-colour bar, 50% marked); stocks up and down; turnover today against
      expected in rupees crore.
   c. Main chart: one bar per minute of turnover, coloured by which side led that minute
      (buying or selling), with the expected turnover as a line; under it, on the same time
      axis, the day's summed net flow as an area with the chosen index's price as a line on
      its own scale; a marker at each watch alert. Crosshair shows the minute's numbers.
   d. "Where the volume is": the stocks table (last, change %, turnover today in crore,
      share of the basket, relative volume 5 minutes and day, spike score, buyers' share as
      a small bar, state chip), sortable by clicking a heading, usable by keyboard.
   e. "Pressure on the indices": one card per index: a bar from selling to buying
      (`pressure_5m`, and the day's as a thin second bar), "the basket explains 93% of its
      minute moves" (`r2`), the top stocks, the text; an index with `trade: false` carries
      the same "Training only" tag the Live Desk uses.
   f. "Order book": buyers' share of resting orders as a bar, the stocks under it, the
      `note`; when `book` is null one plain sentence instead.
   g. "Watch alerts": the session's alerts, newest first (time, title, text, evidence), and
      "Earlier alerts" which loads `/api/volume/alerts`.
   h. "The day's shape": the profile (`/api/volume/profile`): the normal day's turnover by
      minute with its 25th to 75th percentile band and today's line over it; the busiest and
      quietest half hours in words; weekdays; expiry days.
   i. "What history says": the facts of `/api/volume/study`.
   j. "How to read this page": a legend in plain words for turnover, relative volume,
      buyers' share (and that it is an estimate from one-minute bars, not a count of buyers),
      spike, pressure, order book; and the sentence "A watch alert is not a trade alert: it
      tells you where unusual volume is, not what to buy."
3. Behaviour: load on showing the tab; poll `/api/volume` every 20 seconds while the tab is
   shown and the document is visible; never two requests at once; on an error keep the last
   picture and show one small line with the reason; a past date does not poll. Remember the
   chosen index in `OneLot.store` (browser storage, wrapped in try and catch).
4. The fake (`volume_fake.js`, only with `?volfake=1`, with a "Demo data" banner): a full
   session of believable minutes, a spike with an alert, a null `book` on request
   (`&volbook=0`), a closed-market answer (`&volclosed=1`), an error (`&volerr=1`).
5. Looks: phone width (390 px) without sideways page scroll (tables scroll inside their
   card), 1024 and 1440 px; all five themes; charts redraw on theme change and on resize.

## Acceptance criteria
1. Static tests in `tests/volume/test_volume_ui.py` the way `tests/mllab/test_mllab_ui.py`
   and the Simulator's UI tests do it (node lifts pure functions out of the file): the
   formatters (rupees crore, "1.3 times normal", buyers' share), the state texts, the sort,
   the mapping from the contract's `minutes` rows to chart points, the closed-market banner
   rule, the null-book rule.
2. The contract's example body renders without an error in node (a smoke test with a tiny
   DOM stub if the existing UI tests have one; otherwise the pure render-to-string parts).
3. No colour literal: the existing theme tests pass with your files included; no font size
   under 14 px in `volume.css`.
4. The tab is reachable by its number key and by the nav; the other tabs' keys still work
   (update the test that pins the tab order, and say which test).
5. A browser look if you have browser tools: start a private instance from this worktree
   (`(PYTHONPATH=src nohup .venv/bin/python -m onelot run --mock --port 8793 > /dev/null
   2>&1 &)`), open `http://127.0.0.1:8793/?volfake=1#volume`, at 1440, 1024 and 390 px,
   Day and Night themes; fix what you see; stop the instance after (`lsof -nP -iTCP:8793
   -sTCP:LISTEN -t` then kill) and remove the worktree's `data` and `logs` folders.
