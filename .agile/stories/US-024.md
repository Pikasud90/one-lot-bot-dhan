# US-024 — Telegram settings, test message, status and quiet hours

## Story
As the owner, I want to connect my Telegram bot from the Settings tab, send a test, and see delivery health, so that setup needs no file editing and failures are visible.

## Acceptance criteria
- AC1: Given POST /api/settings/telegram with token and chat id, then both are validated (regexes in US-003, newline gives 422), written to .env atomically with mode 0600 even if the file was 0644, the running channel is hot-swapped with replace_channel, and no response or log contains any part of the token (not even the last four characters); the route accepts loopback clients only and requires the session token; a missing or wrong header, including ?token=, gives 401.
- AC2: Given POST /api/telegram/test, then it performs a direct send (not a deduplicated enqueue) of a clearly marked test message and returns its SendResult; GET /api/telegram/status returns configured, last_ok_at, queue_depth, last_error, p95_latency_ms with ISO +05:30 times and no secret; the Settings tab shows them with a Test button.
- AC3: Given a clock outside [09:00, 15:30) IST or a non-trading day per the holiday calendar, evaluated at send time (tests at 08:59:59, 09:00:00, 15:29:59, 15:30:00), then messages are sent silent when notify.telegram_quiet_outside_session is true (default); CRITICAL is never silent.
- AC4: Given notify.telegram false or credentials absent, then nothing is queued and startup logs exactly one INFO line mentioning telegram and no WARNING.
