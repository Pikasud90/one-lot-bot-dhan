# US-112: The wide list's page shows when the round first read a session and from which source

## Story
As the owner, I want the wide list to show when its round first found a session's daily bars and
where they came from, so that I can see when the evening list is ready and why.

## Acceptance criteria
- AC1: Given a round that read session S, when the page asks, then GET /api/desk wide.round has
  bars_seen_at (the time of the first check that found the session's bar, in IST) and bars_source
  ("daily history" today; "quote answer" or "daily history" once US-106 ships).
- AC2: Given a session whose first checks found nothing, then bars_seen_at is the time of the first
  check that did, not the time the round finished.
- AC3: Given a round of a session no check found a bar for (read late), then bars_seen_at is null
  and the page says "read late, the broker's bars had not come".
- AC4: Given the page, then the line "Last round" reads, for example, "session 25 Nov: bars found 26
  Nov 07:32 (daily history), finished 07:41".
- AC5: Given docs/04_OPERATIONS.md under "Waiting for the broker's bars", then "TO BE MEASURED" is
  replaced by the measured hour of at least the two latest sessions, or by the sentence that says
  the figure is a check time, at most 30 minutes after Dhan added the day.

## Non-functional requirements
- A check time is when the desk looked, so the true hour Dhan adds a day is known only to within
  `ROUND_GAP` (30 minutes): the page and the docs say so.
- No new request to the broker.

## Public contract
- `wide_rounds` (`src/onelot/store/schema.py` line 805): its `summary` JSON gains `bars_seen_at` and
  `bars_source`; no new column.
- `_round_view` (`src/onelot/delivery/wide.py` line 1280) returns both; `wideRound`
  (`src/onelot/ui/app.js` line 842) shows them.
- `WideDesk._not_yet` and `run_round`: the first check with the bar writes the two fields once; a
  later try never overwrites them.

## Notes & assumptions

Found in `.agile/sprints/sprint-04.md` (open item 3: "The hour at which Dhan adds a day to its daily
history ... write it into docs/04_OPERATIONS.md") and `docs/04_OPERATIONS.md` ("The hour is not
measured yet"). Verified: the page's "Last round" line has `session` and `finished_at` only
(app.js line 842); `finished_at` is when the tries ended, not when the bars first appeared, so it
cannot show the hour.

The measuring for 25 Nov itself is a read of `wide_rounds.finished_at` in the live store, done by
whoever has the lead's leave to read it; this story makes every later session measured by the app
itself.

Depends on US-106 only for the value "quote answer"; build it after US-106 so that both values
exist. It can ship before, with the one value.

NOT in scope: changing when a round starts or the 30 minute gap.
