# US-000 — Quality gate baseline is green: format, pins, mypy ratchet, repo hygiene

## Story
As the owner, I want one repo-level command that proves the code is formatted, linted, type-ratcheted and tested, and that a fresh clone is complete, so that every later story is held to a green gate that anyone (and CI) can reproduce.

## Acceptance criteria
- AC1: Given a git checkout, when tests/test_repo_hygiene.py runs, then every .py file under src/ is tracked by git (guard against an ignore rule hiding source, as happened to src/onelot/data) and a fresh git clone of HEAD imports onelot.engine, onelot.lab.runner and onelot.desk.desk.
- AC2: Given requirements-dev.txt, then ruff is pinned ruff==0.17.3 and mypy is pinned to one exact version, and pyproject sets ruff extend-exclude for .agile, docs and *.egg-info so Markdown fences are never formatted; ruff format --check . then passes, a second ruff format run produces no diff, and the reformat is behaviour-neutral: for every changed .py file the parsed syntax tree (docstrings normalised with inspect.cleandoc) is identical before and after and the full suite reports the same number of passed tests; the reformat is ONE commit with no hand edits.
- AC3: Given .venv/bin/python -m mypy and NO [tool.mypy], mypy.ini or setup.cfg anywhere (adding one would make the skill gate treat mypy as required), when scripts/mypy_ratchet.py runs against the tracked baseline scripts/mypy_baseline.json (format: _meta with mypy_version and flags, files mapping POSIX repo-relative path to error count), then it exits 0 if and only if the mypy version matches and for every file observed errors do not exceed the baseline (files absent from the baseline count as 0); a decrease exits 0 and prints run --update; a regression exits 1 and lists the files; mypy missing, a crash, unparsable output or errors prevented further checking exits 2 and never 0; --update refuses to raise any count unless --allow-regression is given; a baseline entry for a deleted file warns.
- AC4: Given scripts/gate.sh (no dependency on the Claude skill), when run, then it executes ruff format --check ., ruff check, the mypy ratchet and pytest with addopts including -m not live, and exits non-zero if any step fails; and the skill quality_gate.py run with .venv/bin/python --min-coverage 0 --skip security prints Verdict: PASS.
- AC5: Given CONTRIBUTING.md, then a doc test asserts it lists exactly the commands in scripts/gate.sh plus the ruff format policy.
- AC6: Given the suite, then the story notes record wall_seconds and the five slowest test files (seconds = setup+call+teardown from a junit xml, tolerance 25 percent) with a proposal to shorten them; no behaviour change required.
