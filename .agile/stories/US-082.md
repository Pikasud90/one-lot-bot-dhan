# US-082: a clean standalone version that can be deployed from anywhere

Owner, 2026-11-23: "push it to its repo properly the clean standalone running version such
that it can be deployed from anywhere."

Known defects (from the review of 2026-11-11 and a code map of 2026-11-23):
- `scripts/start_mac.sh` cannot start the app: it runs `python -m onelot --port ...` without
  the `run` subcommand, and `src/onelot/__main__.py: main` only inserts `run` when every
  argument starts with `-`.
- `scripts/stop_win.bat` reads `!ENGINEPID!` without `EnableDelayedExpansion`.
- `pyproject.toml` has no `dependencies` list, so `pip install .` installs nothing the app
  needs; there is no lock file; there is no container file.
- A fresh clone has no market history (it is not in the repo), and the README does not say
  what works without it.

     truth: a test asserts the two agree), and a console script `onelot = onelot.__main__:main`
     if `main` suits it.

     in `requirements.txt` and what they pull in (from `.venv/bin/python -m pip freeze`, with
     local or editable lines removed). The README says when to use it.

   `./data` and `./logs`, reads `.env` if present, publishes the port on 127.0.0.1 only).
   Build it if docker is on this machine; if not, say so plainly in your report.

     Then stop it and remove the temporary folder. Port 8796 only. Fix what fails.
   - `python -m onelot preflight` (it exists): run it on the fresh clone and make its output
     tell a new user what is missing (credentials, history) in plain words, if it does not.
