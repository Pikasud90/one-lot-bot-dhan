# US-110: The spread cap of an option alert is set for each index from measured spreads

## Story
As the owner, I want the widest spread an option alert accepts to be set per index from the spreads
the desk measured, so that FINNIFTY, MIDCPNIFTY and SENSEX are judged on their own market and not
on NIFTY's.

## Acceptance criteria
- AC1: Given config/desk.yaml (or config.yaml, next to option_max_spread_pct) with
  option_max_spread_pct_by_index {FINNIFTY: a, MIDCPNIFTY: b, SENSEX: c}, when an alert for that
  index picks its contract, then a contract whose spread (ask - bid) / ask is above that index's cap
  is not tradeable and one at or below it is.
- AC2: Given an index with no entry in the map, then the default option_max_spread_pct (10) applies,
  and with an empty map every pick equals today's pick (600 healthy random chains, as in US-104 T9).
- AC3: Given an entry outside 1 to 50 or a key that is not an index of the desk, then the
  configuration refuses to load with a message naming the key.
- AC4: Given the fill-cost recorder, then it watches the contract the alert would name for each
  index, with the same cap.
- AC5: Given the fill-cost report, then it also prints, for each index, the median and the 90th
  percentile of the full spread (ask - bid) / ask, next to the cap in force, so that the owner can
  check a cap against what was measured.
- AC6: Given the numbers written in the shipped configuration, then docs/04_OPERATIONS.md names the
  measured date range and the sample count each number came from.

## Non-functional requirements
- The values are chosen from measurements and written in the commit that adds them; nobody tunes
  them to make more alerts pass.
- Nothing about profit: the cap only says which contracts may be named.
- The Lab and the Simulator (model pricing) do not read it.

## Notes & assumptions

Found in `.agile/stories/US-097.md` (the recorded quotes show spreads far wider than the cost model
on FINNIFTY and SENSEX: median half spread about 1.5% of the premium, 7% before 10:00 on SENSEX)
and in `docs/04_OPERATIONS.md` ("FINNIFTY and SENSEX are often wider"). Verified: one number,
`option_max_spread_pct: 10.0`, is read by every index (config.py line 384; economics.py line 312;
desk.py line 313).

What exists today: the fill-cost report gives a HALF spread per instrument; the cap is on the FULL
spread (ask - bid) / ask, about twice the half spread. The first task is to measure the full
spread per index from `fill_quotes` of the live store (a read on a copy, never on port 8787),
write the figures into the story's test log and propose the three numbers to the owner before any
cap changes.

Open question for the owner: how much wider than 10% is acceptable on a thin index; a wider cap
names contracts that cost more to trade, a narrower one leaves more alerts with "no tradeable
contract" (see the decision story US-111).

NOT in scope: the target delta, the expiry choice, the stops and targets, the cost model's 0.6%.
