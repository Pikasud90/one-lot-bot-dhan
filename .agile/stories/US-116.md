# US-116: Every story file has the header the board reads, and the board is current

## Story
As the owner, I want every story file to carry the header the board tool reads and the board to be
regenerated, so that I can see on one page what is built, open and next.

## Acceptance criteria
- AC1: Given .agile/stories/US-097.md to US-106.md (and US-103 once merged), then each starts with
  the front matter lines id, title, status, priority, points, sprint, protocol, created and updated,
  with the status the sprint note gives (merged stories done, US-103 and US-106 backlog).
- AC2: Given the board tool (agile_board.py board), then .agile/board.md lists every story US-001 to
  the highest id, each in the column of its status, and its totals add up.
- AC3: Given a new test in tests/test_repo_hygiene.py, then a story file without the header, or with
  an id that does not match its file name, fails it with the file name.
- AC4: Given the header added to an old story, then its body below the header is byte for byte what
  it was.
- AC5: Given .agile/sprints/sprint-04.md, then it names the board as regenerated and by which
  command.

## Non-functional requirements
- Documents and one test only; no change to src/.
- Prose lines at most 100 characters, as everywhere.

## Public contract
- Front matter shape: see `.agile/stories/US-015.md` and `agile_board.py` (`split_front_matter`,
  `load_stories`, `cmd_board`).
- `.agile/board.md` is generated ("do not edit by hand"); its last run is 2026-11-12.
- `tests/test_repo_hygiene.py`: the new check.
