# US-108: The wide list tells the phone when it releases a paper trade

## Story
As the owner, I want a phone message when the wide list releases a paper trade without the rule's
exit, so that I learn it when it happens if I hold the shares by hand.

## Acceptance criteria
- AC1: Given a wide-list trade released with the reason NO_DATA (a stock that stopped trading), when
  the round releases it, then one message goes out: "RELEASED <symbol>: no daily price for N trading
  days. Paper trade closed at the last close Rs X. No order is placed."
- AC2: Given a trade released with the reason REVIEW (an exit held for a possible split), when the
  round releases it, then one message says the result is not booked because the price basis is in
  doubt.
- AC3: Given a pending entry cancelled for want of data, then one message says the entry was
  cancelled and never filled.
- AC4: Given the same release is read again after a restart or a second try, then no second message
  is sent (dedup key `delivery:<signal id>`).
- AC5: Given the channel refuses the message, then the release stays in the book and the message is
  tried again after RETELL, as the entry and exit alerts are.

## Non-functional requirements
- Nothing in the message promises a result or says to buy or sell.
- A failure to send never stops the round or changes the book.
- Words as plain as the entry and exit alerts of the same list.

## Public contract
- `WideDesk.alert_text(t, which)` and `WideDesk.notification(t, which)` in
  `src/onelot/delivery/wide.py` (today `which` is the entry or the exit alert), `WideDesk.tell(now)`
  with `self.book.untold()` and `self.book.mark_told(t.id, which, now)`.
- A new `which` value, for example `"release"`, and a field on `WideTrade` that records that the
  release was told (the same `told` mechanism as the exit alert).
- Exit reasons `NO_DATA` and `REVIEW` and the status `CANCELLED`, as US-103 defines them.

## Notes & assumptions

Found in `.agile/stories/US-103.md` on branch `story/US-103-wide-no-data` (head `d416f23`), section
"Decisions": "Nothing is sent to the phone on a release ... the page is where they learn of it",
and again under "Not done": "No message to the phone on a release".

Depends on US-103 (NOT yet merged on 25 Nov 2026): the release, `NO_DATA`, `REVIEW` and `CANCELLED`
do not exist on `main` or on the sprint branch until it is. Do not start before it is merged.

Why it matters: the wide list is a paper test, but the owner may hold the same shares in a real
account. A release changes what the rule says about them (the rule's own exit will never come),
and the page is a poor place to learn it.

NOT in scope: any other message of the wide list; a message when a stock becomes dormant but still
has no release (the release is the event). Open question for the owner: one message per release,
or one daily summary line when several come together (the default here is one each, at most ten a
round, then one line "and N more").
